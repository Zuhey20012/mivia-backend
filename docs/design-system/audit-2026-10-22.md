# Birch Market design system: audit (22 Oct 2026)

## Summary
**Apps reviewed:** customer (91 files), store (50), courier (44) | **Shared code:** none | **Score:** 48/100

The visual language is strong and consistent in spirit: Bricolage Grotesque + Hanken Grotesk, sunshine accent, pastel tiles, stadium buttons. What it lacks is a *system*. Tokens exist only partly, every app has its own copy, and screens hard-code most values.

## Token coverage
| Category | Defined in theme.dart | Hard-coded in screens (customer / store / courier) | Notes |
|---|---|---|---|
| Colours | 64 / 17 / 20 hex values | 161 / 68 / 52 hex literals + 230 / 99 / 93 `Colors.*` | Dark mode depends on each screen choosing correctly; `Colors.grey.shade500` contrast bugs already found |
| Typography | display + body helpers | 383 / 180 / 138 `fontSize:` literals, **22 / 20 / 17 different sizes** | A real type scale needs about 8 sizes |
| Radius | radiusLg etc. | 169 / 74 / 51 literals, **22 / 12 / 12 different radii** | A scale needs 4–5 values |
| Spacing | none | 347 / 246 / 179 `EdgeInsets` literals | No spacing scale at all |
| Motion | none | 20 / 10 / 7 different durations | Needs 3 durations + 2 curves |
| Elevation | ad-hoc shadows | — | Needs 3 levels |

## What best-in-class teams do (patterns used as references)
- **Wolt** (Wolt's design system is public on wolt.com/design): one token set across consumer, merchant and courier apps; strong use of whitespace; a single primary action per screen; skeletons that match the final layout; motion only on state changes.
- **Zalando** (Zalando's public design system): a strict 8-point spacing grid, a small type scale, and filter chips plus sort as one consistent pattern on every list.
- **Sephora / Lyko**: shade swatches as first-class components, ingredient and "how to use" sections as collapsible panels, and the unit price always under the price.
- **Material 3 and Apple HIG** as the accessibility floor: 48 dp touch targets, 4.5:1 text contrast, Dynamic Type / text scaling, and reduce-motion support.

## Priority actions
1. **Create `packages/malvoya_ui`** with one token set:
   - colours as semantic roles (surface, onSurface, primary, accent, success, warning, danger, plus app accent: Malva / Moss / Lingon), light and dark;
   - type scale (8 sizes);
   - spacing 4-pt scale (4, 8, 12, 16, 20, 24, 32, 40);
   - radius (8, 12, 16, 24, pill);
   - elevation (3 levels);
   - motion (fast 150 ms, base 240 ms, slow 400 ms; standard and emphasised curves).
   Each app passes only its brand accent.
2. **Build the core components once**, each with states, a loading variant, semantics and golden tests: MButton, MTextField, MSheet, MChip/MFilterBar, MSkeleton, MStateMessage, MSnack, MPrice/MUnitPrice, MSwipeConfirm, MSwatch, MSizeSelector, MBadge, MListTile, MSectionHeader.
3. **Create `packages/malvoya_core`** for the 20 duplicated service files: API client, auth, agreements, app gate, push, socket, strings and l10n, and one merged server-message table.
4. **Migrate screen by screen**, replacing literals with tokens. A lint check in CI fails new hex, `fontSize` or `EdgeInsets` literals outside the package.
5. **A gallery app** (`packages/malvoya_ui/example`) showing every component in light, dark, Finnish and large text. It doubles as the golden-test source and as living documentation.
